        How it works

        Five steps turn pasted text into a number. No machine-learning library is involved: the model is a weighted sum written from scratch.

        1. Normalise the text

          Lowercase it and collapse every run of whitespace into a single space, so a phrase split across a line break is still found.

          "WE ARE A FAST-PACED,
   DYNAMIC team"  →  "we are a fast-paced, dynamic team"

        2. Count eleven signals

          Phrase lists and a few patterns turn that text into eleven numbers — the only thing the model ever sees. It has no access to the company, the role, or whether anyone was hired.

        3. Put them on one scale

          A word count in the hundreds and a yes/no signal of 0 or 1 cannot be compared directly, so each is rescaled using the average and spread measured during training.

          standardised = (value − average) ÷ spread

        4. Add them up

          Each standardised signal is multiplied by its learned weight and summed, starting from a constant called the bias.

          z = bias + (w₁ × x₁) + (w₂ × x₂) + … + (w₁₁ × x₁₁)

        5. Squash it into a probability

          That sum can be any number at all, so the sigmoid function folds it into the 0–100% range.

          probability = 1 ÷ (1 + e^−z)

        The eleven signals

        Read straight from the model file, so this list cannot drift from what was actually trained.

          Why logistic regression, and not something bigger?

          • The explanation is the model. Each signal's push is literally a term in that sum, so the breakdown you see on a result is the arithmetic itself, not a guess about it made afterwards.
          • The dataset is small. A more flexible model would memorise a couple of hundred postings rather than learn from them.
          • It is small enough to ship. Eleven weights and a bias is a few kilobytes, which is why the whole thing can run in your browser and your text never has to leave your device.
          • The trade-off: it cannot learn that two signals only matter in combination. A tree-based model could. With this much data, that is worth giving up.

          About & limits

          What this tool can and cannot tell you, and why it is built the way it is.

          Please read this before trusting the score

          • This is a heuristic, not a detector. It compares wording against a small set of postings labelled by hand, by one person. It has no access to the company, the role, or whether anyone was ever hired.
          • Nobody can know a posting is a ghost job from its text. The training labels are educated guesses. A model trained on guesses reproduces those guesses.
          • Do not let this talk you out of applying. Plenty of real jobs are written badly, and plenty of ghost postings are written well. A high score is a prompt to ask about timelines and the team, not a reason to walk away.
          • It is biased toward what it was trained on. Postings from other countries, industries or languages may score oddly.

          Your text stays on your device

          There is no server. The trained model is a small file of numbers your browser downloads once, and the scoring happens locally in JavaScript. Nothing you paste is uploaded, logged or stored. You can disconnect from the internet after the page loads and it will still work.

          How the training data was built

          Every posting in the training set was labelled by hand, one at a time. The hard part is that nobody can know a posting is a ghost job by reading it, so each label also records the evidence behind it: the posting had been up over a month, the same role kept being reposted, an application went unanswered.

          Labels based only on how a posting reads are tracked separately, because the model's signals come from the wording too. Training on those alone would teach it to agree with one person's hunch, so the training script warns when too many labels are of that kind.

          Built as a learning project

          The logistic regression is written from scratch in plain Python — the sigmoid, the log-loss, and the gradient descent that fits the weights. No scikit-learn, no numpy, no external AI service. The full write-up, including the design decisions and the known weaknesses, is in the repository.
